# Process Overview

This area explains how documentation is structured and maintained, how work is
tracked, how repository changes are verified, and how accepted releases move
toward production.

It exists so humans and agents can find the smallest useful set of docs,
understand how those docs should be used, and keep the docs tree synchronized
as repository truth changes.

Read the focused docs here for routing, the indexed docs system, transitional
states, co-located docs, terminology maintenance, Markplane tracking,
verification, or releases. Read `conceptual-simplicity.md` when a task affects
boundaries, decomposition, terminology, or docs structure.
